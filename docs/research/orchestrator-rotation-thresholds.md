09.10.2026. Джерело: закріплене завдання оператора в Delegatus.

Linux, i9-12900K; Bun 1.4.0, Next.js 16.3.6, Claude 2.1.284, Codex 0.160.1. Viewer зібрано в експорті під `/tmp`, з окремими `LLV_STATE_DIR`, `HOME`, `TMPDIR`, конфігураціями й портом. Реальні JSONL копіювали, обрізали по цілих рядках і дублювали з переприв'язаними ідентичностями. Оригінали та чинну seat не змінювали. Для Codex використано окремі реальні транскрипти його формату: текст 2,12 / 8,43 / 20,51 / 40,48 MiB, зображення 2,03 / 8,05 / 20,09 / 40,02 MiB. Успішний resume повертав один початковий turn. MCP і Viewer у таблиці читали Claude-серію; усі HTTP-відповіді — 200.

1. **Обрано: залишити 50% свіжого активного контексту як ранню пораду; прибрати 8 MiB і дві компакції з причин ротації.** Viewer після 8 MiB не має стрибка витрат до 40 MiB. Повна історія дорожчає для CLI: запит Claude зріс із 0,86 до 17,13 MiB для тексту та з 2,28 до 40,08 MiB для зображень. Байти мають реальну ціну читання й серіалізації, але межа 8 MiB не обґрунтована. Токени стосуються активного бюджету моделі. Оптимальність 50% і якість відповідей не вимірювали; підвищувати поріг до 80% підстав немає. Порада сама не запускає ротацію.

2. У `src/lib/orchestrator/health.ts:368–414` прибрати причини `transcript` і `compactions`, лишити інформаційні байти та «компакції, помічені у хвості». Нині **два справжні Claude `system/compact_boundary` дають лічильник 0**: `src/lib/session/reader.ts:178` розпізнає старі `type: compact/summary`, а `src/lib/mcp/bindings.ts:4118–4131` рахує тільки trace `compact`; Codex `ContextCompaction` має іншу назву. Нормалізувати native-події спільно без нового повного сканування. Доказу, що саме друга компакція вимагає ротації, немає; копія з двома межами й малим usage відновилася без третьої.

3. **Виправити свіжість usage перед застосуванням 50%.** У `health.ts:125–198` зупиняти пошук на новішій межі компакції: сильна порада потребує usage після неї. Відтворення: ручний `/compact` записав `preTokens=980010`, `postTokens=1249`, збільшив файл із 2,01 до 2,24 MiB; нинішні facts усе ще повернули **980000** із старого provider usage. До нового usage показувати «непідтверджено»; `postTokens` — оцінка CLI. Fallback за всією історією дав для текстових копій 0,53 / 2,10 / 5,25 / 10,51 млн токенів. Оцінювати доведений активний сегмент після стискання або повідомляти «невідомо».

4. Узгодити фактичне вікно в `contextPolicy.ts:37`, `bindings.ts:4129`, `src/app/api/orchestrator/seat/status/incumbent.ts:159` та `src/components/orchestrator/seatState.ts:396`. Повторно використати визначення місткості з `src/lib/scanner/context.ts:58`, з перевагою runtime-вікна та явного режиму запуску. Локальний stub: `opus` повідомив **200000**, `opus[1m]` — **1000000**; при однакових 318903 токенах перший сам компактував, другий — ні. Це контроль режимів; конфігурацію чинної seat не перевіряли. Невідому місткість лишати невідомою. Чинна політика 50% охоплює тільки Claude; Codex має невідомий поріг.

5. Перевірки майбутнього виправлення: свіжий usage нижче 50% на всіх восьми копіях не дає пораду за байтами; дві native-межі відображаються правильно; старий usage перед компакцією не створює сильну пораду; 49%/50%/51% працюють для підтверджених 200k та 1M; оцінка ніколи не стає `strongly_recommend`. Перевірити обидва серверні шляхи, fallback панелі, незмінність seat та відсутність автоматичної ротації.

Межі читання пояснюють таблицю: панель — **768 KiB**, історія — **4 MiB** (`src/lib/logRead.ts:11,64`); рядок через межу дочитується частинами. API сесії та MCP seat розбирають останні **8 MiB** (`reader.ts:67`), прибираючи зображення з текстової відповіді; панель рендерить їх окремо. Сканер ділить хвіст **128 KiB** й початок до **4 MiB / 41 рядка** (`src/lib/scanner/activity.ts:55,286`). MCP messages: блоки **256 KiB**, бюджет **16 MiB**; визначення автора додатково читає весь малий файл або обмежений сусідній сегмент великого (`src/lib/session/messagesPage.ts:14,235`). Поле `scanned` не включає всі ці читання. Fallback контексту робить повний первинний прохід: 4–87 ms, потім кеш. Ротація залишає старі файли й не скорочує каталог архіву.

Пошук історії й пам'яті знайшов дизайн від 08.10.2026, який уже відкидав оцінку за байтами після компакцій; висновок звірено з кодом. [Claude Code](https://code.claude.com/docs/en/how-claude-code-works) описує очищення tool outputs і стискання біля межі; [Codex App Server](https://developers.openai.com/codex/app-server) — native resume. Stub вимірює клієнтську роботу; тарифікацію, затримку провайдера та якість стислого контексту цей дослід не оцінює.

## Deferred — not currently justified

Нові межі 20/40 MiB, автоматична ротація й новий сервіс метрик не обґрунтовані. Дослід якості та тарифікації потребує справжнього провайдера. Код продукту в цьому етапі не змінювався.

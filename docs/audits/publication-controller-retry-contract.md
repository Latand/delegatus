# Controller publication retry fixture contract

Requirement, paraphrased from the secondary board record dated 2026-11-03:
publishing an unchanged commit after an environment change must obtain fresh
applicable checks; an explicit retry of a refused publication must renew its
check evidence. The original operator turn remains unrecovered. Private
conversation quotations and record identifiers are omitted.

## Exact cases and controls

**A — `controller publication renews cached checks after environment drift on the same head`.**

1. Create a fresh native fixture and non-expiring HTTP remote. Freeze HEAD,
   tree, merge base, tool bytes, explicit Git configuration and host epoch after
   setup. Set `LANG=C` for A and `LANG=C.UTF-8` for B. Normalize all other inputs,
   including the publisher's `NODE_OPTIONS` default, before seeding. Build the
   seed environment using `pipelinePublicationHookEnv`; retain the native Git
   PATH behavior and production check-environment projection.
2. Under A, call the existing `f.run(true)` preparation and `f.run(false)` native
   hook with a separate fixture operation. Both must exit 0; no remote RPC is
   made. A second fresh fixture operation under A must reuse types, lint and
   touched-test passes. Consume each seed receipt through the real hook.
3. Change only LANG to B, then call the raw controller publish action and its
   durable publication consumer. Require renewed applicable heavy commands,
   including `touchedChecks(f)`, and a real receipt bound to the reserved id,
   epoch, fence, SHA, destination ref and observed remote head.
4. Require preparation before transport, exactly one Git push and one accepted
   RPC, a settled successful operation, `publishedCommit` equal to the accepted
   SHA, and the bare remote ref equal to that SHA. Assert unchanged HEAD/tree
   and preserved stage verdict/attempts. Repeat the settled publisher consumer:
   no additional preparation, push or RPC.

The A-to-A warm operation is the reuse control; A-to-B is the invalidation
control. Compare receipt components: environment changes while source, base,
toolchain, Git configuration and plan remain equal. An accidental second input
change invalidates the fixture proof and must be corrected before diagnosis.

**B — `explicit controller publish replaces a consumed environment refusal on the same head`.**

1. Use another fresh fixture. Publish through the same raw action and native
   consumer under A. Immediately before its first real `git push`, read the
   valid prepared receipt and capture its operation id, binding and components.
   Change only the fixture's forwarded LANG to B at that boundary; leave the
   command, receipt and all other caller fields intact.
2. Forward the original native Git command. Require nonzero exit and the gate's
   environment-component mismatch. Inside the exec observer, after `realExec`
   returns and before returning to the publisher's cleanup, require both the
   receipt and its `.consuming` path absent. This distinguishes real hook
   consumption from the publisher's later unconditional removal.
3. Require zero receive-pack RPCs, absent destination ref, unchanged HEAD/tree,
   no `publishedCommit`, and a durable settled refusal for the old operation.
   Retain its journal/result evidence before renewal. A running or uncertain
   operation is insufficient input for this step.
4. Keep B and invoke raw explicit `publish` again with the same accepted SHA.
   Require a different persisted pending operation id. Execute its actual
   consumer; require a newly bound receipt, fresh applicable B checks, one
   confirmed remote publication, preserved accepted-stage evidence and no
   residual receipt paths. The earlier refusal must remain observable in
   retained history/journal evidence. Count two attempted pushes overall and
   one successful remote write.

For a source red control, in an immutable scratch copy only, change the explicit
publish call to `queuePipelinePublication` so it no longer requests the settled
result recheck. B must fail its fresh-reservation assertion. Restore the
unmodified source in a fresh export and run the complete file green. The
deliberate mid-handoff drift is itself the transport refusal control. Preserve
the failure evidence; never manufacture a receipt or bypass its validator.

# Idle seat delivery and incoming failure recovery

An adopted broker retained a consumed input from its previous writer without a terminal boundary. The native ledger counted that input against the replacement writer's three-input window. A later intent could fail before append, while the broker retained its new in-memory input fence. Subsequent idle sends were rejected as stale turns. Seat monitoring tracked individual wakes and host loss without accumulating consecutive incoming delivery failures.

The ledger now applies admission capacity to the current writer lineage. Previous-writer evidence continues to fence its original key. The in-memory ledger window retains only the latest writer's active payloads; historical lookups still read durable evidence. A typed capacity refusal raised before append removes only the newly allocated in-memory state; an unknown append or sync outcome retains its fence. Native admission receipts identify the refusing component and predicate. Progress records retain the latest allowlisted refusal across phase-history eviction, settlement and reopening, including first/last observation and a bounded repeat count. Busy queue observations identify the earlier effect kind and phase.

Terminal delivery writers update a constant-size recipient health summary in their existing registry transaction. Successful delivery resets the failure streak; uncertain outcomes retain protection. The tick reads that recipient row and begins recovery after two proven failures have persisted for the existing fifteen-minute delivery-alarm bound. The existing host recovery owner records a frozen nudge, identity-fenced idle-host cleanup, shared composer revival and the existing lost-host rotation fallback. Each phase survives a fresh controller, including unfinished cleanup with retained descendants. Busy turns, permissions, background activity, provider waits, unreadable evidence, operator controls, seat changes and release fences withhold recovery. Cleanup rechecks ownership before each signal through the existing termination ladder. Recovery starts on the first eligible check after the alarm bound. The ordinary ten-minute settlement window still decides an admitted nudge's fate, and cleanup and revival advance on subsequent checks. An ownership hold keeps its reason and original delivery identities. No throughput or latency improvement is claimed.

## Verification

The real broker, file ledger, owned transport process and adoption regression failed on the merge base at native intent persistence before the implementation changed. The repaired sequence admits the current writer's full input window, completes its inputs, accepts another input from idle and never rewrites the previous writer's consumed input. Separate fault cases cover a definite capacity refusal and an append whose reply is lost, including host restart and original-key replay protection.

Recipient tests cover JSON and SQLite persistence, terminal correction, duplicate outcomes, legacy missing fields and a bounded keyed read with unrelated retained history. Seat tests cover the recovery phases, their board reason, fresh controller instances, busy/uncertain ownership holds and cleanup of the actual idle broker that refuses admission. All execution checks use private state, home and temporary directories and a closed Viewer control endpoint. Final command results are recorded with the pull request.

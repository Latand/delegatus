## Amendments after the first review

The review overruled or sharpened four points of the plan above; the code follows these.

- **An explicit ask to send again resends.** `asked_again` now sends a waiting or answered request once more under its own delivery key, once per operator turn. A retried tool call, an unmarked repeat and a model rewording still send nothing. A `pending_request` handle that names a request to another project is refused for recomposition and never absorbs the new ask. A turn that repeats a waiting request and asks something new passes the repeat by handle and sends only the new part.
- **Answer coverage is the seat's word.** The send asks the seat to set `answersDirective` on `bridge_report`: true closes the request whatever the class, false keeps it waiting. Without it, `completed`, `review_verdict` and `failed` answer; `status` is progress; `question` and `blocked` keep the request waiting and are shown as the orchestrator asking back.
- **A report is relayed whole or refused.** The complete copy is never shortened: a report past 8 KiB is refused before anything is stored, with a request to split it (`report_too_large`). Section items are no longer sliced at 32 before rendering, and an older caller's body lines keep their full text in the complete copy while the display cuts them.
- **Speech is owed durably.** The scan that finds a report records it as owed to the voice in the same commit (`StoredSession.reportSpeech`). Its parts are fixed at the first hand-off, and the number the provider took is committed after each one. A failed hand-off resumes at that part on the next poll, later reports wait behind it, and no part the provider took is handed again. On Codex the adapter refuses a part once its call has failed or is stopping, and voices each part only after the previous output finished (slice 2). After an interruption the report stays whole in the transcript and in `orchestrator_reports`, so the voice reads it again on request instead of repeating parts blindly.

## Choice and trade-off

Use the existing backing model to resolve pending question references, existing proposal storage to enforce their lifecycle, and one retained speech queue per session. A prompt-only change leaves pending-state and payload-loss defects open. Exact-text deduplication misses rephrasing. An external semantic service or a second relay introduces unnecessary ownership and ordering boundaries. The remaining model judgment is explicit: both backend fixtures must exercise rephrasing and answer coverage, and normal recorded acceptance must check actual speech. The requirement justifies the small state and delivery extensions; it requires no backend replacement or new UI.

## Deferred — not currently justified

Embedding services, a new workflow/queue framework, larger retrieval budgets, model replacement, capability expansion, backend-switch UI changes and redesign of the older bridge hook. The required work fits existing proposals, report storage, backing models and provider adapters. This stage publishes only the authorized note; it introduces no UI variants or prototype media.

# One source of truth for agent state

Design baseline: `b457a8585518e382bec595c3103d5b0bedf9a0fd`. Source inspection: 2026-11-12, beginning at approximately 20:48 UTC. Line references below refer to that baseline unless a parallel lane is named. This stage changes this document only. It performs no production cleanup, restart, or product modification.

The outcome is one evidence model and one evaluator, with different evidence acquisition paths for an owned host, a cached reader, and reconciliation. `activeTurnRef`, conversation turn state, runtime session status, scanner activity and browser badges become projections. A projection cannot grant permission to send, signal a process, replace an owner, settle a delivery, or remove a checkout.

## Observed problem and earlier answers

The brief reports 121 agent processes, 66 held hosts and seven turns doing work; 55 released hosts consume 11.1 GB RSS. Twenty-six released hosts have been silent for over six hours. One reported Codex turn has a native completion six and a half days before its still-open registry reference. These are supplied incident observations, not a census repeated by this design stage. The orchestrator separately owns the approved immediate cleanup and its stopped-host report.

The causal path is present in this checkout:

1. Each engine adapter derives `HostState.activeTurnRef` from its own memory: Codex `currentState()` at `src/lib/runtime/codexAppServerHost.ts:3587`, Claude at `src/lib/runtime/claudeStreamBrokerHost.ts:1416`, Copilot at `src/lib/runtime/copilotAcpHost.ts:736`.
2. `codexHostColumns`, `claudeHostColumns` and `copilotHostColumns` copy that field into registry host columns (`src/lib/runtime/registry.ts:124–187`). `bindStructuredHostPersistence` queues the owning host's checkpoints under its writer claim (`:270–618`). A released claim has no callback advancing its cache.
3. Retirement refuses immediately on a non-null reference (`src/lib/runtime/structuredHostRetirement.ts:401–409`), then separately checks the conversation's turn and entry status (`:411–416`). Its transcript check only stats mtime (`:463–479`); it never compares the native terminal boundary with the cached reference.
4. Resources obtains `turnBusy` from `conversation.turn.state` and `owned` from a process-local delivery-host lookup (`src/lib/runtime/structuredHostControl.ts:42–103`). `resources.ts:602–607` adds a separate owned/released/orphaned label. The two readers can disagree without either seeing the other's evidence.
5. Retirement candidates currently select only Claude and Codex (`structuredHostRetirement.ts:1047–1053`), although the resource inventory includes Copilot. Startup explicitly leaves Copilot resume to a subsequent message (`src/lib/runtime/startup.ts:3164–3169`). Slice 1 must cover this branch too.

Project-scoped and unscoped transcript searches for stale turn references, retirement and one agent-state authority found the current originating brief and earlier partial repairs. Memory searches found prior bounded-retirement work; it provides no existing implementation of this outcome. Current code was checked against [true-agent-activity.md](true-agent-activity.md), [update-drain-liveness.md](update-drain-liveness.md), [copilot-engine.md](copilot-engine.md), and [runtime-journal-startup.md](runtime-journal-startup.md). Those designs explain useful safeguards: bounded evidence, a separate unknown answer, process-and-artifact identity, and retained delivery custody. Their older line numbers and vocabularies do not determine this design.

## Module contract

Add `src/lib/agentState/` with a pure `model.ts`, native `transcript.ts` adapter/cache, `service.ts` for the serving owner, and `store.ts` for bounded persistence/read projection. The public barrel exports the pure model separately from server entry points. Browser code imports the pure projection adapter only. Existing native protocol state machines collect facts; one `evaluateAgentState(facts, now, policy)` defines state and reason. No new general orchestration framework or ADR is needed.

The primary subject is an exact host generation, keyed by engine/session key, canonical conversation binding, generation id, process pid/start/boot, writer claim/epoch and transcript artifact identity. A conversation may have multiple generation/process subjects. Evaluate them independently; aggregate after evaluation. A live predecessor stays visible even when the current generation changes. Aliases resolve conversation display/scope; they do not merge process evidence. A discovered stamped process without a registry binding gets a process subject and incomplete conversation facts. External native sessions use a verified external-harness owner kind; absence of a Viewer claim alone does not make them a managed unowned host.

### Facts and evidence

Every fact uses the existing `Determinable<T>` union from `src/lib/runtime/determinable.ts`. A determined value carries an evidence envelope. Null represents proved absence only. Unknown carries its reason and last attempted read time. The response keeps these distinctions through serialization.

| Fact | Value and evidence required |
| --- | --- |
| Process | `alive`, `dead`, or undetermined; full recorded and observed identities, namespace/domain, zombie/may-run status; source `proc` or platform backend; observed-at and identity token. `dead` describes the recorded process. A recycled pid names a different process and cannot be signalled. |
| Owner | Held by this Viewer, verified other Viewer, verified external harness, proved absent, or undetermined; owner process identity, writer epoch, release identity, held transport binding/revision. A live claim with no answering host is unresolved ownership. |
| Turn | Open, closed, absent, or undetermined; native turn id when available, local host turn reference separately, native opening/closing record type, order/offset/UUID, terminal outcome, and timestamps. Preserve an open turn after process death as interruption evidence. |
| Attention | Exact pending question/permission refs with kind and generation/turn binding, or proved empty; source host memory/current native control evidence. A stale restored RPC request is visible and cannot be answered as a live request. |
| Transcript | Trusted artifact binding, device/inode, size, mtimeNs/ctimeNs, bytes/offset read, integrity, newest complete record time, last filesystem write time and boundary coverage. mtime measures writes; event timestamps measure events. Neither supplies identity. |
| Activity detail | Verified open tools, wait/check, background tasks, provider retry and actual work progress, each bound to the same subject/turn with observation/expiry. Keep existing ownership validation. Capability flags are separate from activity flags. |

Evidence fields: `source`, `observedAt`, `eventAt` when supplied, `validUntil` for volatile observations, `subjectRevision`, and a bounded source reference (native record type/id/offset or host seq/file identity). Keep raw engine text, command arguments, credentials, environment and account details out of projection/journal rows. A source can be `host-memory`, `native-transcript`, `registry-cache`, `proc`, `runtime-writer-mark` or `operation-ledger`. The authoritative chosen fact also retains losing evidence needed to explain a disagreement.

A verdict contains `state`, `reason`, `since`, `evaluatedAt`, `policyVersion`, `projectionRevision`, `coverage`, and per-field evidence. `state` is one of the six requested states when evidence determines it; otherwise `state: null`, `quality: unverified` and the missing facts. ### One definition of the six states

Evaluate in this precedence, retaining all underlying facts even when a higher state wins:

| State | Definition | Consequence |
| --- | --- | --- |
| `dead` | The exact recorded agent process can no longer execute, under the platform identity/may-run probe. Missing pid evidence is insufficient. | Keep interrupted/open-turn facts and survivor obligations. Replacement still needs all writers/tree/scope proven ended. |
| `unowned` | The managed process is proved alive and no valid Viewer host binding holds it; claim-owner death/release is proved. | Keep its open/closed turn and attention facts. Reconciliation selects adoption, protection, or retirement below. Unknown owner stays unverified. |
| `waiting-operator` | A live owned agent has a current unresolved question or permission requiring operator response. | A matching permission/question blocks ordinary dispatch and retirement. An unanswered tool call or provider retry alone is a different reason. |
| `stuck` | A live owned agent has a verified open turn and the transcript has been silent for at least the shared stuck threshold, initially 10 minutes. | Diagnose silence; keep turn open. Verified check/background/provider-wait detail explains the silence and suppresses automatic “worker stopped” escalation as today. Silence never grants interrupt, completion or retirement. |
| `working` | A live owned agent has a verified open turn below that silence bound. | Detail can say executing, checking, provider retry or starting accepted work. Admission before the first native record is explicit bounded provisional evidence, never an invented native start. |
| `idle` | A live owned agent has a proved settled/absent current turn, with no current operator attention. | Age is measured from transcript write evidence. Queues, setup/operation custody and retained scope can still refuse retirement. |

The `stuck` counter counts verified silent open turns even when the primary state is `unowned`; it uses the same underlying predicate. The “normal 0” target is operational: every nonzero row needs a reason, including a verified long check. Existing check suppression remains; the module does not mislabel check silence as an operator question or end its turn. Primary state, activity detail, ownership and operation custody remain available together.

One policy object owns thresholds and versioning: 10 minutes for stuck diagnostics; retirement idle defaults to one hour, with the existing environment override; existing startup grace is five minutes. The pipeline's 12-minute threshold is an action grace during migration, named separately from agent state. S3 removes its duplicate classifier while retaining any necessary longer recovery deadline explicitly. Provider retry clocks, delivery deadlines, recent-file styling, and retention have their own meanings. No caller passes an arbitrary “idle after” value to obtain a different state.

## Acquisition, caching and cost

The serving Viewer process that owns structured delivery publication owns the service. Start it from `src/instrumentation.ts`/the existing startup lifecycle after state ownership and serving-release admission; stop scheduling and revoke its generation token on demotion before releasing hosts. MCP processes, resource collectors, files workers, the browser and the runtime host read projections or receive facts. None independently starts reconciliation. Server/runtime readiness continues to use its existing probes; incomplete reconciliation does not block unrelated startup or claim server health.

| Reader | Evidence path | Cost and freshness contract |
| --- | --- | --- |
| Owned host send/steer/answer/interrupt/native queue | Synchronous host-memory facts plus current writer/generation/attention fence, evaluated by the pure module | O(1) bounded fact check; zero transcript/proc I/O on each send. After each awaited preparation/read, reacquire a synchronous current fact/fence immediately before dispatch. Existing health methods can remain async compatibility adapters. |
| Board, resources, MCP activity/fleet, seat tick, viewer snapshot | Validated persisted projection, then process-owned cache; revisioned deltas | Keyed O(selected rows), no tails/process census per read. | Reconciliation | Current hot host page plus changed registry/host facts; stat bound transcript, read strict tail only on changed identity/mtime/size | O(live subjects + changed tail bytes) per full cycle; O(changes) between cycles. Join one pending read per artifact/subject. No whole retained-registry/corpus read per request or tick. |
| Retirement | Request central refreshed facts for the addressed batch, then all existing obligation checks | Same cached native evidence when stat is unchanged; current owner/process and obligation checks before effects. | Heap series | S5 samples central aggregate/counter artifact | O(1) aggregate read; no new census, GC or transcript read. Heap allocation/object counts stay separate measurements. |

Initial budgets are implementation limits, not measured speed claims: reconcile every two minutes with a persisted fair cursor; event-driven coalesced invalidation on host/claim/attention change; up to 32 subjects per page, four concurrent tail reads, 30 seconds total pass work before deferring the cursor. A page yields to the event loop at least every eight milliseconds. Maintain a due-time queue for the 10-minute stuck boundary so an unchanged transcript can change state without rereading bytes. A one-hour age qualifies on a subsequent retirement pass, whose existing five-minute cadence and batch/grace budget stay intact.

Tail cache key: engine, canonical artifact binding, device/inode, size, mtimeNs and ctimeNs. Using mtime and size alone would accept same-size replacement. Start with 128 KiB, matching `readStableTailRecords`. Reuse that reader's pre/post-fstat, pathname identity, UTF-8 and complete JSON validation (`scanner/activity.ts:288–352`). Before spending evidence on a durable write, recheck file identity and subject revision. A changing/torn/unreadable tail remains undetermined and schedules a bounded retry. Empty complete tails prove no terminal boundary. Truncation, rotation and same-size replacement invalidate offsets and parsed boundary state.

If the required start/end lies outside 128 KiB, read backward in bounded pages to a maximum 4 MiB per acquisition, then checkpoint cursor/fold state for a later pass. Do not treat the limit as an idle answer. Each artifact-version cache owns its parsed summary, incomplete-line carry and boundary coverage; it releases raw buffers after reduction. Continuous append folds only the changed suffix with overlap/record validation, capped to the same page budgets. A persisted anchored summary permits the next process to validate the stat signature and refine it, rather than scanning an old multi-megabyte turn on its first request.

An incomplete boundary acquisition may resume earlier unread pages of that same version under a labelled recovery job. It never rereads an unchanged completed tail or restarts from the end on every pass. Cache metrics distinguish this bounded outstanding recovery from a cache hit, and a changed file version invalidates its unfinished cursor.

Cache bounds: 4,096 subject summaries, 16 MiB aggregate parsed evidence, 256 KiB summary per exceptional subject, four I/O buffers in flight. Evict inactive least-recently-used summaries first; remove bindings/listeners immediately on release/generation removal. Active subjects over the capacity stay in the durable indexed population and are paged fairly; eviction yields cache misses and visible incomplete coverage, never a false idle. Process/owner observations expire within five seconds for display; actions always revalidate the exact identity. Attention/tool references have bounded counts and a visible truncated/unknown marker if exceeded. No body, transcript or event-window array is retained by this service.

The atomic mutation for one subject does the following:

1. Confirm serving release/generation and exact observed registry tuple: key, process, writer claim/epoch, current artifact binding, turn ref, conversation turn revision/observation and retained obligations. The asynchronous collection work finishes before this mutation. A replaced owner, new prompt, moved tail or new delivery invalidates the proposal.
2. For unowned/dead-writer rows, fold verified native evidence and update the `activeTurnRef` cache and compatible conversation turn together. A matching terminal clears the stale ref; a later native start remains open. Native open state without a known host ref is represented explicitly in the projection; do not mint a send-authority ref from a timestamp. For owned rows, synchronously ask the current host to refresh its facts; a delayed transcript never clears a newer in-memory turn. A proven native divergence under an unchanged owned turn is repaired through the host's adapter, then checkpointed. An incompatible host observation stays a journaled unresolved divergence and refuses effects.
3. Write the projection, a transition/divergence row and counter deltas in the same transaction. A divergence is journaled even if primary state remains `unowned`, and even if a later action is refused. Journal insert failure rolls back the cache repair. A no-change observation changes no row/revision merely to restamp it.
4. Publish the committed revision to read clients and the runtime-host compatibility projection outside the transaction. The runtime host accepts only the matching generation/writer/reconciliation revision. A failed publish is a durable pending projection obligation retried with the same key; it does not undo a repair or settle a send. Startup replays pending publications before trusting older runtime turn words. Effect callers still need the local host fence during this interval.

“Transcript wins” applies to a complete, correlated native observation of the turn in question, including every released host. A newer owned-memory event is evidence of a later turn and must survive an older transcript terminal. A queue admission that has not materialized is explicit pending work. There is no path that calls a plain non-null registry string authoritative after this migration.

Journal fields: stable event id/revision, subject/conversation/generation, old/new primary state (including unknown), old/new turn/cache, reason, actor Viewer pid/start/boot and release revision, observed/effective timestamps, and bounded evidence refs. Use one row for a state transition with an optional divergence payload; a divergence without a transition still gets a row. Permission/owner replacement, adoption/retirement selection, refused action and unresolved boundary are separately named observations. Existing physical stop journal remains the record of signals/results; reference its operation id instead of duplicating its payload.

Retain journal rows for at most seven days and at most 16,384 rows, whichever removes earlier; series for at most 24 hours/1,440 minute samples; keep at most 4,096 terminal subject projections for 24 hours. Active unresolved subjects remain addressable and visible with paged coverage. Prune in bounded pages outside hot requests; no indefinite pending publication holds an entire log. Counter totals survive pruning and serving restart. Collection rows are bounded to 8 KiB (summaries refer to compact separately bounded native evidence); no automatic journal export enters a public report. Pruning uses existing collection/key order and bounded selectors, not collection materialization per tick.

## Deferred — not currently justified

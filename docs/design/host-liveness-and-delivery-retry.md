# Host liveness, retirement and recipient-scoped delivery retries

On 2026-11-24 the operator requested one decision about the live host, the unfinished turn and retirement eligibility (#4283), followed by retries addressed to the recipient and the owner of each unfinished action (#4287). The 2026-11-20 architecture review, §4, lines 41–49 and §8, lines 83–91, is the originating technical requirement. The two issues share a design because a retry needs to know which owner can still act on which generation.

**Decision.** Extend the serving Viewer’s agent-state evaluator to answer for one exact host and turn. Let each effect owner verify that answer at the point of action. Schedule delivery work by obligation, with one controller timer for the earliest due obligation. A confirmed stop, a completed registration and a delivered message each require their own evidence.

### Contract between the two lanes

#4287 enumerates source rows. Given one of those rows it can ask #4283 for the subject and relevant facts. This is the proposed synchronous interface at the effect boundary. An unavailable fact carries its source and reason through the existing `Fact<T>` type. Times are Unix milliseconds. The caller checks the original source row, admission order and current transport immediately before acting. A scheduled callback cannot authorize itself. `src/lib/agentState/model.ts:6–29,54–81`, `src/lib/runtime/structuredDeliveryController.ts:1086–1095`, `src/lib/agent/registry.ts:12925–12968`.

```ts
type WorkKind = "launch" | "control" | "migration" | "delivery" | "handoff"
  | "native-queue" | "background" | "flush" | "realtime" | "descendants"

type HostWorkQuery = {
  conversationId: string
  generation: SessionKey
  action?: { kind: WorkKind, sourceId: string }
}

type HostWorkAnswer = {
  subject: string
  generation: SessionKey
  process: AgentFacts["process"]
  owner: AgentFacts["owner"]
  writer: Fact<{ release: string, claimOwner: string | null, claimEpoch: number,
    writerClaimEpoch: number | null }>
  turn: AgentFacts["turn"]
  attention: AgentFacts["attention"]
  semanticRevision: string
  validUntil: number
  counts: Fact<Partial<Record<WorkKind, number>>>
  actionPresent: Fact<boolean> | null
  retirement: { clause: string | null, eligible: Fact<boolean>, reason: string }
}

type InspectHostWork = (query: HostWorkQuery) => Fact<HostWorkAnswer>
```

Counts cover the queried subject. A missing kind in a determined count is zero. A read of 33 candidate keys from any bounded source or more than 32 combined obligations yields `unknown("obligation coverage truncated")`. An unreadable source names its own failure. Both withhold ordinary retirement. A query with an action checks its exact key and holder even when totals are unknown. Without an action, `actionPresent` is null. A send proceeds only with its own required facts, custody and ordering checks. No consumer infers the absence of other work from a keyed hit. Seed 40 held deliveries for one recipient. Give the fixture an intact process, closed turn and no earlier veto. Retirement must return the truncation reason. All 40 deliveries must retain distinct due keys and drain in admission order, and every serialized projection must fit the 8,192-byte reader limit. Main's bounded reads, string-list fact and byte check are at `src/lib/agentState/service.ts:38–66,359–379`, `src/lib/agentState/model.ts:63,245–261`, `src/lib/agentState/store.ts:43–51`.

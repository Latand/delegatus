# Open a conversation by identity

**Operator requirement, 20 November 2026, paraphrased.** Opening a designated seat on desktop or phone should read one conversation. Its durable ID, an alias and a recorded former path should reach the same current transcript, even when it has aged off the board. Keep the board summary for screens that display it. After migrating the direct readers, remove the pinned cache variants that legacy links no longer require. Section 1 of the 20 November architecture review is recorded publicly in issue #4280, “Open a conversation by identity instead of building the board”, under Proposal and Deletion test.

**Decision.** Give the existing conversation pane one authorized entry from `GET /api/conversations/entry`. The registry resolves the identity, the scanner describes one file, and a single mounted client reader serves the dock, phone sheet and phone conversation. Address the seat by its durable ID as soon as the designation is known. A board refresh, catalog publication or successful incumbent poll must never be a prerequisite for opening it. This specializes phase 1 of the merged owner-facts design. The parent design supplies the route, authority rules and wire limits. Main source references use revision `d435b522a35f973f943d611e66a0348606f27116`. (`docs/design/unified-owner-facts.md:87–97,148–165,175–189`.)

## One read for a known identity

Accept exactly one nonempty query value, `conversationId` or `path`. Reject duplicates, extra keys (including project), malformed or oversized values with 400. Proposed input limits are 4 KiB per decoded identity and a 16 KiB encoded query, allowing a 4 KiB path even with percent encoding. Validate the query before any store read. Return one `{file: SeatEntry, attention: SeatAttentionObservations}` on 200. The identity fields are the canonical conversation ID and generation when registered, current readable path, engine/format, authoritative project and display title. A legacy scanner-only entry can have a path identity. The feed keeps its own message transport. Every entry response is private, no-store, including failures. Conditional requests receive the same fresh authority check. (`docs/design/unified-owner-facts.md:91–97,154–165`, `src/lib/types.ts:151,340–342`, `src/components/orchestrator/OrchestratorConversation.tsx:43–88`.)

1. **Resolve under one registry read.** Add a sibling to `sessionTarget` that returns detached entry facts. Reuse its asynchronous cold-open admission and skip cold-key initialization. Resolve the ID alias chain with a visited set and a 64-hop bound, or read the owners of the exact generation/continuity path and canonicalize them. Require one distinct owner. Read that owner's project, generation, title, launch facts and materialization receipts at the same revision. The reverse map already has a composite primary key and insert/update/delete triggers. Keep the normal release-fenced import and readiness check. An ID lookup can proceed while a reverse map is unavailable. An incomplete map cannot prove a path is unregistered. The existing first-owner and caller-path fallback in other APIs are unsuitable as proof. (`src/lib/agent/registry.ts:11057–11086,13978–13994`, `src/lib/agent/sqliteRegistryStore.ts:2092–2126,5553–5564,5720–5730`, `docs/design/unified-owner-facts.md:93–94`.)
2. **Select the readable generation.** Use the receipt fence, including finalized same-identity resumes and staged/abandoned paths. A former path names its owner even after the old file disappears. Once a newer authoritative materialized generation is identified, a missing file there yields a missing result. A surviving predecessor with the same ID cannot replace it. Honor the already-readable source during a same-path resume. A known pending materialization gets 409. Alias cycles, an exceeded traversal bound, conflicting owners and unready identity evidence get retryable 503, subject to the disclosure rules below. Only path-mode lookup with a complete reverse-map miss can try a legacy file. A failed ID lookup never becomes a filesystem search. (`src/lib/agent/identityMaterialization.ts:28–44,55–93`, `docs/design/unified-owner-facts.md:91–95,179–185`.)
3. **Describe one physical file.** Extract the scanner metadata part of the pinned-descriptor read. Open an admitted regular file inside a registered root, disallow a leaf symlink, validate resolved containment, and recheck device/inode and any sidecar before returning. Use asynchronous descriptor I/O on the Viewer. Preserve the MCP tail/session callers and the pipeline's one-line read. Respect scanner engine mapping, including Antigravity. The MCP adapter itself overlays session titles and limits its return to two engines. Those defaults belong to that adapter. (`src/lib/mcp/bindings.ts:3188–3237,3298–3315,3325–3358,3362–3376`, `src/lib/scanner/activity.ts:176–182`, `src/lib/pipelines/fromConversation.ts:76`.)
4. **Bound the work.** One abortable open budget of two seconds starts with the user's intent. Cold designation discovery, lock admission, file I/O and final checks spend its remaining time. Cancel on navigation. Label waits and outcomes under `conversation.entry` without logging IDs or paths. Use at most 64 KiB of header and 64 KiB of metadata tail, at most 64 KiB of sidecar metadata, and a 64 KiB encoded entry. Keep identifiers intact. Trim optional display text, or fetch large actionable detail separately by its authorized ID. For example, after 1.6 s spent on discovery and identity, at most 0.4 s remains. A busy optional source never receives a new budget. A 70 KiB optional prompt can contribute a clipped display label and an opaque action reference. A manual retry starts a new intent. (`docs/design/unified-owner-facts.md:96,154,167–171,183–189`, `src/lib/state/lockWait.ts:147–163`.)

### Cold project-only open

Use a current, authorized designation immediately. Otherwise send only `project` and `view=identity` to the project seat GET. Select the keyed authority mode in middleware and the workspace wrapper. In the handler dispatch this view before `scope=all`, `resolveSeatProject` and `seatRecordReconciled`. On main the name resolver consults `lastScannedProjectCatalog()` and `lastScannedFiles()`, joins the project set with task, pipeline, flow and archive membership, inspects roots on disk and can record successions. The full GET can also reconcile a pending launch. The identity view performs zero calls to those two scan readers, `resolveSeatProject`, `namedProjectDirectory` or either mutation. Succession stays with its existing writers. The full status GET is the sole caller of launch reconciliation. When the identity view reports a pending spawn or an accepted launch still awaiting its transcript, show pending immediately and keep the full status reader polling until the launch settles. Its result can supply a ready designation or a terminal failure. (`src/app/api/orchestrator/seat/route.ts:102–136,223–237`, `src/lib/orchestrator/seatProjectIdentity.ts:132–158,166–171`, `src/lib/projects/nameResolution.ts:60–76,89–96`, `src/lib/scanner/scanCache.ts:1166–1178`.)

Pin the validated project-alias snapshot and use its revision-cached inverse from the owner-facts design. Accept a durable project key or an exact recorded predecessor that resolves to one. Probe the slot and placement keys under the canonical key and its recorded predecessors. Normalize contenders, choose the current epoch and check manager authority, workspace reach and alias revision before returning. No display-name lookup, cwd hint, traversal of the alias directory per request, or scan-slot initialization belongs to this branch. The identity read does no history, task or deputy listing. Enable full status for that pending launch or for controls consuming those details. A ready designation goes straight to the entry. (`src/lib/projects/identity.ts:20–24`, `src/lib/projects/aliases.ts:65–95`, `src/app/api/orchestrator/seat/route.ts:157–184`, `docs/design/unified-owner-facts.md:102–106,123–137,175–179`.)

| Input with the process catalog empty | Identity-view response |
| --- | --- |
| Display name without an exact recorded key, ambiguous syntax, or extra query keys | 400. The client obtains the key from its project selection. |
| Former key with a proven alias | Same authorized slot as its current key, even if only the former slot row exists. Return canonical conversation ID, epoch and authorized path. A disappeared designation path still starts the entry read. |
| Well-formed key with no slot or pending intent | 200 vacant for a principal independently allowed to read that project or an unrestricted owner. This answers whether a slot exists for the key. An unknown, unplaceable key gives a restricted reader generic 403. No names or alternatives are disclosed. |
| Pending intent, revoked claim, unavailable proof | Return pending or revoked to an authorized reader. On unavailable authority or conflicting evidence return generic 503. A denied reader gets the same refusal across all states. |

### Descriptor and attention on upgrade

The entry reads the scanner descriptor by exact `project_catalog` keys `meta` and `f:<path>`. Verify its version, resolution state, generation where applicable, and the identity of the file and sidecar. The registry owns the generation, project and rename. The scanner owns transcript observations. The current cached-row reuse checks allow an unchanged ten-day-old file to bypass description indefinitely. (`src/lib/scanner/projectCatalog.ts:140–149,196–208,246–266,290–303`, `src/lib/scanner/projectCatalogStore.ts:39–49,70–102`.)

**Writer.** Bump `PROJECT_SUMMARY_VERSION` from 4 for the scanner format change. The next ordinary persisting catalog pass re-describes the retained inventory, including transcripts outside the board shortlist. Each release accepts only its own summary version. With a single writer the upgrade costs one corpus pass. If two releases alternate persisting the inventory during handover, each switch of writer version can cost another corpus pass. Record elapsed time, files re-described, bytes read and rows rewritten for each pass separately from click latency. Produce the bounded descriptor with the board's single-file fact readers during that pass. Persist transcript-derived facts and completeness by group. Re-evaluate host state, clock-dependent attention, grants and dismissals at read time. Carry it through `cachedFile`, the explicit `nextFiles` copy, decoder, field allowlist and write comparison. Compare its value so a second unchanged scan writes zero changed descriptors. A predecessor can overwrite a row with the old field list during handover. Treat the stripped row as a cache miss immediately and regenerate it on the next current-writer pass even with unchanged size and mtime. Only the scanner schedules this pass. (`src/lib/scanner/projectCatalog.ts:259–289,402–404,428–429,444–468,558,652`, `src/lib/scanner/projectCatalogStore.ts:98–102,139–159,185–202,703–719`, `src/lib/scanner/index.ts:353–398`.)

**Before that pass.** Within the header, tail and sidecar limits above, return the validated path, root, kind, engine, format, size, mtime, authorized title and any observed cwd, start time and parent. Use current registry ownership/title and the same keyed live host, turn, ask, dismissal and routing inputs as for a descriptor hit. Decode context, pending question and input wait only when the bounded records establish them, including the board's answer, supersedence and live-process checks. A missing record in a clipped window cannot establish absence. A missing historical turn boundary, context sample or action prerequisite stays unresolved. Render the messages immediately. If the evidence proves the winner, render its reason, route and dismissal, including an observed absence. While a retryable source is being read, show “Checking attention”. At the deadline settle incomplete history or a still-busy source as “Attention unavailable” with Re-check, suppress dependent actions and retain the draft. A subsequent successful refresh can replace that state in place. (`src/lib/mcp/bindings.ts:3325–3357`, `src/lib/scanner/questions.ts:105–151`, `docs/design/unified-owner-facts.md:150–171`.)

Apply the parent design's full field-to-owner inventory and its bounded, once-per-read attention probes. Apply the board's finished-owner, dismissal, expiry and routing rules at one clock. Only a current manager proof routes the seat's own reason to the operator. Excess protected bridge rows or unavailable evidence leave only their dependent decisions unresolved. A session selector can start the tab-wide runtime bus. Keep that shell traffic visible and use an already-live observation or keyed session capabilities for the first message. (`src/app/api/files/response.ts:691–702,939–970`, `src/lib/attention/routing.ts:114`, `src/hooks/useRuntime.ts:54–69,174–179,543–550`, `src/components/orchestrator/seatState.ts:663–682`.)

### Refresh of a mounted seat

On main, a live board follows `files.revision`, seat status polls every six seconds, and the phone card takes its row from the board and enables its own incumbent read when the sheet opens. The feed already consumes authorized log chunks. The server emits a chunk for each batch containing appended bytes, so using a chunk to start an entry GET would make metadata traffic follow transcript throughput. (`src/hooks/useFiles.ts:1725–1732,1967–1975`, `src/components/orchestrator/useOrchestratorSeat.ts:12–15,157–182`, `src/components/mobile/MobileSeatCard.tsx:211–229`, `src/hooks/logBus.ts:174–195`, `src/lib/logTailStream.ts:176–188,215–235`.)

**One refresh clock per visible selection.** The shared entry reader starts the initial GET immediately and records its monotonic start time. While the same seat is visible, schedule the next automatic GET six seconds from the last actual start, using the seat poll cadence even when full status is unmounted. Allow one request in flight. A late timer takes one sample and schedules from that start. Only this clock starts automatic reads. Each sample reconciles the current transcript, runtime, expiry and dismissal state, including Undo. Resume or reconnect can use the next eligible start. Attaching the sheet to the card joins the existing selection. Suspend reads while hidden and retain the last start across visibility changes. On access loss clear the entry, feed and actions immediately. A changed principal or designation requires a fresh authorized open. (`src/components/orchestrator/useOrchestratorSeat.ts:138–155,157–188`, `src/lib/asks/controller.ts:78–84`, `src/lib/attention/reconcileController.ts:124–126`, `docs/design/unified-owner-facts.md:165–175`.)

**Cost and freshness.** For a pane with a feed and a card with its sheet closed, the reader can start at most ten automatic entry GETs in any half-open 60-second window for the same visible selection, even during continuous appends. Count the initial open against that allowance and count every failed or aborted start. An explicit Re-bind or manual retry is a new user intent, measured separately, and its start also sets the next automatic deadline. Each read spends at most two seconds on registry admission, bounded metadata (up to 192 KiB), one probe per capped source and final authority and generation checks. Ten 64 KiB entry bodies total at most 640 KiB per minute. An open pane continues streaming messages as they arrive. A card without a feed starts zero log subscriptions or tail polls. A question committed just after a sample, or a remote dismissal with no log event, must update the visible badge on either surface within eight seconds on a healthy connection with the sources available. This trades up to six seconds of badge latency for a fixed read rate. The two-second initial-open budget still applies. (`src/components/orchestrator/OrchestratorConversation.tsx:64–80`, `src/hooks/logBus.ts:86–95,174–195`, `docs/design/unified-owner-facts.md:154,171–175,183–189`.)

### Which pins lose a reader?

Opening the seat by identity removes its array lookup and refresh. **Zero pinned cache variants lose their last reader at this revision.** The following decisions apply to navigation in the same release. “Board pin” means the existing conditional pin, including release on close.

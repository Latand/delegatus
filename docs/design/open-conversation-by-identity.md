# Open a conversation by identity

**Operator requirement, 20 November 2026, paraphrased.** Opening a designated seat on desktop or phone should read one conversation. Its durable ID, an alias and a recorded former path should reach the same current transcript, even when it has aged off the board. Keep the board summary for screens that display it. After migrating the direct readers, remove the pinned cache variants that legacy links no longer require. The requirement appears in section 1 of the architecture review, `ARCHITECTURE-REVIEW-20261120.md:11–19`, and issue #4280, “Open a conversation by identity instead of building the board”, Proposal and Deletion test.

**Decision.** Give the existing conversation pane one authorized entry from `GET /api/conversations/entry`. The registry resolves the identity, the scanner describes one file, and a single mounted client reader serves the dock, phone sheet and phone conversation. Address the seat by its durable ID as soon as the designation is known. A board refresh, catalog publication or successful incumbent poll must never be a prerequisite for opening it. This specializes phase 1 of the merged owner-facts design. The route, authority rules and wire limits there are implementation requirements. Main source references use revision `1b63d879a75bc2abbc0328a86315840ff48d4643`. (`docs/design/unified-owner-facts.md:87–97,148–165,175–189`.)

## One read for a known identity

Accept exactly one nonempty query value, `conversationId` or `path`. Reject duplicates, extra keys (including project), malformed or oversized values with 400. Proposed input limits are 4 KiB per decoded identity and a 16 KiB encoded query, allowing a 4 KiB path even with percent encoding. Validate the query before any store read. Return one `{file: SeatEntry, attention: SeatAttentionObservations}` on 200. The identity fields are the canonical conversation ID and generation when registered, current readable path, engine/format, authoritative project and display title. A legacy scanner-only entry can have a path identity. The feed keeps its own message transport. Every entry response is private, no-store, including failures. Conditional requests receive the same fresh authority check. (`docs/design/unified-owner-facts.md:91–97,154–165`, `src/lib/types.ts:151,340–342`, `src/components/orchestrator/OrchestratorConversation.tsx:43–88`.)

1. **Resolve under one registry read.** Add a sibling to `sessionTarget` that returns detached entry facts. Reuse its asynchronous cold-open admission and skip cold-key initialization. Resolve the ID alias chain with a visited set and a 64-hop bound, or read the owners of the exact generation/continuity path and canonicalize them. Require one distinct owner. Read that owner's project, generation, title, launch facts and materialization receipts at the same revision. The reverse map already has a composite primary key and insert/update/delete triggers. Keep the normal release-fenced import and readiness check. An ID lookup can proceed while a reverse map is unavailable. An incomplete map cannot prove a path is unregistered. The existing first-owner and caller-path fallback in other APIs are unsuitable as proof. (`src/lib/agent/registry.ts:11057–11086,13978–13994`, `src/lib/agent/sqliteRegistryStore.ts:2092–2126,5553–5564,5720–5730`, `docs/design/unified-owner-facts.md:93–94`.)
2. **Select the readable generation.** Use the receipt fence, including finalized same-identity resumes and staged/abandoned paths. A former path names its owner even after the old file disappears. Once a newer authoritative materialized generation is identified, a missing file there yields a missing result. A surviving predecessor with the same ID cannot replace it. Honor the already-readable source during a same-path resume. A known pending materialization gets 409. Alias cycles, an exceeded traversal bound, conflicting owners and unready identity evidence get retryable 503, subject to the disclosure rules below. Only path-mode lookup with a complete reverse-map miss can try a legacy file. A failed ID lookup never becomes a filesystem search. (`src/lib/agent/identityMaterialization.ts:28–44,55–93`, `docs/design/unified-owner-facts.md:91–95,179–185`.)
3. **Describe one physical file.** Extract the scanner metadata part of the pinned-descriptor read. Open an admitted regular file inside a registered root, disallow a leaf symlink, validate resolved containment, and recheck device/inode and any sidecar before returning. Use asynchronous descriptor I/O on the Viewer. Preserve the MCP tail/session callers and the pipeline's one-line read. Respect scanner engine mapping, including Antigravity. The MCP adapter itself overlays session titles and limits its return to two engines. Those defaults belong to that adapter. (`src/lib/mcp/bindings.ts:3188–3237,3298–3315,3325–3358,3362–3376`, `src/lib/scanner/activity.ts:176–182`, `src/lib/pipelines/fromConversation.ts:76`.)
4. **Bound the work.** One abortable open budget of two seconds starts with the user's intent. Cold designation discovery, lock admission, file I/O and final checks spend its remaining time. Cancel on navigation. Label waits and outcomes under `conversation.entry` without logging IDs or paths. Use at most 64 KiB of header and 64 KiB of metadata tail, at most 64 KiB of sidecar metadata, and a 64 KiB encoded entry. Keep identifiers intact. Trim optional display text, or fetch large actionable detail separately by its authorized ID. For example, after 1.6 s spent on discovery and identity, at most 0.4 s remains. A busy optional source never receives a new budget. A 70 KiB optional prompt can contribute a clipped display label and an opaque action reference. A manual retry starts a new intent. (`docs/design/unified-owner-facts.md:96,154,167–171,183–189`, `src/lib/state/lockWait.ts:147–163`.)

**Cold project-only open.** If the parent already holds a current authorized designation, use its ID immediately. Otherwise request `view=identity` on the project seat GET. Return the winning active slot's canonical ID, epoch and authorized path, or a distinct vacant, pending, revoked or unavailable state. Then do the one entry read. This discovery step is necessary only when the caller starts with a project. The existing full GET also reads history, can enumerate seats or tasks and computes `exists` from the designation path. Let controls request that detail independently. A missing original path must still start resolution. (`src/app/api/orchestrator/seat/route.ts:102–112,135–136,160–162,180`, `src/components/orchestrator/useOrchestratorSeat.ts:206–215,352–354`, `docs/design/unified-owner-facts.md:175–183`.)

**What the pane may infer.** Use the complete field-to-owner inventory in `docs/design/unified-owner-facts.md:150–169`. Read the versioned descriptor by exact `f:<path>` and meta keys from the scanner's persisted catalog. Validate file and sidecar identity. Populate it during normal scanner ingestion. A missing or old descriptor falls back to bounded metadata. Keep the user's renamed title and the authorized display fallback. Use an already-live runtime observation or fetch capabilities for this identity. A runtime selector can start the tab-wide bus, and Re-check can request a full runtime refresh. Keep any independent shell traffic visible in the trace. An isolated seat must never launch a whole-runtime refresh to obtain its first message. Evaluate the same title, attention, dismissal, finished-owner and routing rules as the board with single-row inputs. The seat's own reason routes to the operator only with current manager proof. Present each optional group as observed (including observed absence) or unresolved. Probe each capped source once, with row and byte limits before decoding. Over-budget protected bridge rows, for example, leave the bridge observation unresolved. A busy attention store permits the feed to open with “Checking attention”. It cannot clear a wait or enable a control. Refresh once per source change/expiry, coalesced while mounted, without remounting the composer. ## Authorization through the first message

Register the entry as a project read. Apply the same targeted decision to designation discovery, entry, first log POST, stream subscription and batches, and session GET. Preserve batch semantics for other paths in the same log request, the feed's root/relay policy, and the session route's engine support. Main currently builds a workspace scope in middleware and again in the route wrapper, and its conversation resolver consults the process catalog. The stream has a further per-batch callback. Merely changing the entry handler would leave a restricted cold open dependent on the directory and catalog before it could show a message. (`src/lib/team/gate.ts:187–202`, `src/lib/team/workspaceRoutes.ts:89–90,110–111,177–179`, `src/lib/team/workspaceRoute.ts:21–66,215–231,270–319`, `src/hooks/logBus.ts:92–100,179`, `src/app/api/logs/route.ts:45–69`, `src/app/api/logs/stream/route.ts:11–22`, `src/app/api/session/route.ts:18–34`, `src/lib/externalRelay/feedAccess.ts:15–21`.)

The middleware checks that the member holds a membership in an existing workspace. For each requested reference and resolved artifact, use one pinned project-alias snapshot and its inverse raw keys. Point-read placements, discard deleted workspaces, and apply the existing canonical-key, earliest-placement, raw-key tie break. Read the member's own memberships. An unplaced known project is readable by a member with manager membership. Probe **every raw alias key** in both the published project set and curation. On a cold catalog use authoritative ownership of this conversation to establish its project. Include the matching raw key/source in the decision evidence. For a bound agent, read the binding by **exact stored ID at each ancestor**, including a caller whose manager proof fails. Keep designated/message/launch precedence and workspace narrowing.

## 3. Retire executable review-loop; load old definitions safely

**Chosen option:** remove `review-loop` from the new execution grammar after a compatibility release. Keep a legacy decode type and a pure conversion function. New API creates and graph edits accept `run` stages; archived records can still contain the old discriminant. Existing readers currently require run/review-loop shapes and enforce graph reachability (`src/lib/pipelines/store.ts:351-443,492-545,614-628`), so changing the TypeScript union alone would drop valid stored records.

**Rejected option:** a permanent review-loop compiler on every execution would retain another public stage kind, another budget vocabulary and translation on every read/edit. A one-time, explicit conversion achieves the required graph while keeping history legible. The prior ADR also selected removal (`automation-v2/adr/0001-one-record-extend-pipeline-retire-flows-and-workflows.md:24-34`). No new ADR is needed to repeat that decision. This document changes its proposed archive behavior: history has active readers because the present requirement explicitly demands readability.

Proposed conversion rules:

1. Load hot rows, archived rows and draft definitions using the existing legacy shape first. Rendering, export and GET never migrate or launch anything. Preserve original stage id, prompt, resolved runtime, task ids, spec, base ref, publication policy, old attempts, `flowId`, `reviewFlowSync`, decisions and artifacts. Unknown fields survive raw archive export. Evidence requiring both stores: R-PIPELINES and `pipelines/store.ts:800-808`.
2. For an unstarted legacy stage with a known preceding run, preview a reviewer `run` stage using the old stage id and pass successor. Add one dedicated fixer `run`, with a deterministic collision-checked id, followed by the reviewer; the reviewer fail edge targets that fixer. Give the fixer the existing implementer role snapshot and findings input, preserving declared task/spec context. Re-running an arbitrary predecessor could repeat deployment or planning, so conversion must not choose it as a fix stage merely because it precedes review. Existing predecessor lookup is at `pipelines/engine.ts:1632`; this is new migration behavior.
3. Translate a finite flow review limit N into the equivalent bounded review count under the corrected #1938 semantics. The conversion test must prove N actual reviewer activations, including the final review, rather than equating unlike counters. Refuse silent clamping, ambiguous role selection, stage-count overflow or zero/unlimited limits. Keep such a definition loadable and show an editable conversion preview with a recommended finite limit of five; start stays refused until the graph validates. Existing stage limits and reachability validation remain authoritative (`pipelines/engine.ts:4621-4921`).
4. Conversion requires an explicit revision-fenced pipeline action before start/retry. Startup only decodes records. Persist the converted definition and an immutable original-definition snapshot in one pipeline mutation; the acceptance receipt is idempotent. Preserve completed attempts as historical legacy entries, separate from new run attempts. An old approval never marks the converted review passed. The existing attempt binding and historical flags provide the model (`pipelines/engine.ts:2795-2798,6209-6214,6575-6579`).
5. Completed/closed records need no conversion to remain readable. Drafts in either store can be restored and previewed. The paused unsafe-relay flow and its associated lane are excluded from automatic conversion, task reassignment, host cleanup and all flow-driven pipeline reconciliation. The snapshot does not establish that every parked pipeline is that lane; match by stored `attempt.flowId` during a later authorized migration, then preserve the matched lane byte-for-byte. New work can be a separately authorized pipeline with a reference to this history; migration never creates one automatically (R-OPEN, R-PIPELINES).
6. A record already holding live flow-owned execution at release time is a cutover preflight failure. Do not kill it or infer completion from stale activity. Wait for a safe, settled state or obtain a separately scoped disposition. The measured snapshot is reassuring, but execution must recheck under the release fence immediately before enabling retirement (`flows/types.ts:121-146`; R-OPEN).

During the compatibility release the converter is available but optional, and the original engine remains available for existing execution. At cutover all flow actuation is refused. Thereafter an unmigrated legacy stage is readable and visibly retired; start/retry returns a migration-required error with the preview route. No loading path invokes the converter.

## 4. Archive, the open flow and approved history

**Proposed archive:** retain the existing SQLite `flows` collection in place and move its reader to `src/lib/reviewHistory`. Add a bounded, project-filtered `/api/review-history` list and `/api/review-history/[id]` detail, plus an archive pane reachable from task/stage history and project history. Keep flow ids as archive ids to preserve links. An on-demand export contains original row data and available round artifacts; export stays private and does not enter fixtures or documentation. No second database, dual archive writer or mandatory bulk export is justified (current collection and artifact seams: `flows/store.ts:177-207,324-354,559-579`).

The archive labels the recorded outcome and recorded review SHA/date. It shows missing artifacts as missing, stale or unavailable heads as unknown, and the paused row as **Retired — delivery unresolved**. Its original paused state, error, receipt ids and round remain unchanged. Archive status is a read-model label. The 29 approved rows keep their verdicts and identity; retirement neither closes them nor marks them merged or reviewed at today's head. All 303 closed rows remain addressable (R-FLOWS, R-OPEN).

Preserve exact settled relay attribution. `relayProvenance.ts:52-67` only uses delivered rounds; uncertain accepted deliveries produce no settled occurrence. Moving the relay id and formatter must retain the same bytes, including old retry/binding behavior (`flows/engine.ts:409-413`). Never synthesize delivery evidence from a verdict or from retirement itself.

Disable writer admission by code across the two processes before removing engine code. Leave stored controller flags and collection revision intact for the frozen row; the runtime no longer schedules the collection. Stop flow ownership reconciliation and merged-flow evidence writes, including scanner and account-migration hooks; archive readers canonicalize conversation aliases without rewriting rows (`flows/store.ts:356-460`; `reaperRuntime.ts:237-255`). Keep registry memberships, delivery receipts, event decoders and artifacts needed to explain history. A lifecycle/reaper branch may be removed only after proving it owns no surviving general executor or pipeline host.

Legacy import remains owner-fenced and idempotent for supported installations that have not migrated. Imported rows enter the frozen archive and never start controllers. Keep rollback mirror/checkpoint plumbing for supported releases (`src/lib/state/hotStateMigration.ts:25-41`; `src/lib/viewerInstrumentation.ts:328-368`). Retirement does not accelerate #1872's date or two-release condition. When #1872 lands, remove the archive reader's legacy import/mirror paths together with other stores; keep the SQL rows and historical artifact reader. Apply that issue's legacy-file guard and incident behavior, with tests that unimported input cannot silently vanish (R-ISSUES).

Rollback after freeze is a patched release that keeps retirement admission closed. Rolling back to an arbitrary pre-retirement binary could resume the unsafe relay or mutate archived rows. Preserve pre-conversion definitions for controlled definition rollback only while no new attempt has executed; after execution retain attempts and use a forward repair.

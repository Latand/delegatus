# Read current owners in the Update dialog

Section 5 of the 2026-11-20 architecture review calls for Update to find possible blockers from current owners, unfinished launches, deliveries and their links. Issue #4284 carries that requirement, including on-demand history, an explicit full audit and fresh verification at the switch. The 2026-11-24 order selected this item for design. Code references below use main at `6d629874` unless a PR revision is given.

## What the operator waited for

The measured request was the authenticated Update event stream. The installation state arrived first. Each reading eventually reported incomplete work evidence. The times below end at that fresh result. The bytes are HTTP registry JSON decoded during the single longest Viewer event-loop pause. The first read on the new release spent longer fetching pipeline and runtime evidence than on the previous release. Other requests were running in the same process. The 2026-11-20 architecture review records the observations in §5, line 55. Issue #4253, comment 7029183655, gives the paired measurements for the two releases.

## Where the current read spends its work

1. Snapshot GET and the event stream opt into work by default. The service shares one observational read, returns the installation immediately and reuses a landed result for five seconds. The read runs the custody form of `probeQuiet`. Its instrumentation builds a phase map from pipeline attempts and flow rounds. 2. The worker calls registry health, the pipeline list and the flow list. Registry health reads both pipeline collections on its unprepared path. The worker's protocol carries the pipeline and flow arrays. The Viewer buffers stdout, parses it at exit and replays the answers. The owner reader separately obtains its registry and flow inputs. Moving the same arrays to another thread still leaves their transfer and decoding on the opening path. 3. The census projects every conversation's generations and continuity paths, visits entries and receipts, and considers every stored headless round. The full census answers questions such as which earlier launch shared an artifact. The dialog needs that history only when a current claim points to it. ## Full audit and switch

Offer **Run full audit** as a deliberate operator action in Update. Start it only by POST after the server’s `operatorGate` checks origin and operator authority. Share one running audit, perform its historical census off the Viewer loop, and return progress, source errors and paged findings tagged with audit time. Include all receipts, generations and old reviewer rounds. Published observations continue while it runs. A refresh, SSE reconnect, background health sample or partial result cannot start an audit. Assert zero audit starts for an ordinary snapshot, an SSE reconnect, `work=audit` on either GET, and cross-origin or unauthorized audit requests. Preserve the installation-only `work=0` path. The current route treats every other value of `work` as true, so an audit needs explicit dispatch. (`src/lib/selfUpdate/routes.ts:21–26`, `:54–81`, `src/lib/lifecycle/owners.ts:270–286`, `:299–331`, `:340–369`.)

The switch takes fresh evidence at its existing authority boundary. Read the current target, request, gate, launcher PID and start identity, serving generation, live work identities, controller state and drain policy again after asynchronous waits. Rediscover new starts as well as rechecking previously seen owners. Preserve the full authoritative census for decisions that require it. A display limit, a cached empty observation, an audit timestamp or a client-supplied list grants no permission. Checkout compares dispatch versions and gate ownership before reservation. The launcher checks again before taking the request and after its load check. Managed auto admission also re-reads reachability and live work. An explicit override covers only the work its admission allows. Manual checkout revalidates the durable apply request, launcher identity and dispatch version after the build. Managed operator requests go to the deployment owner. Neither receives authorization from the dialog. (`src/lib/selfUpdate/service.ts:690–717`, `:1034–1052`, `:1083–1122`, `:1134–1148`, `:1167–1173`, `:1539–1561`, `:1643–1666`, `:2071–2079`, `src/lib/selfUpdate/quiet.ts:546–561`, `:571–578`, `:606–621`.)

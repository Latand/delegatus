## Where the current read spends its work

1. Snapshot GET and the event stream opt into work by default. The service shares one observational read, returns the installation immediately and reuses a landed result for five seconds. The read runs the custody form of `probeQuiet`. Its instrumentation builds a phase map from pipeline attempts and flow rounds. (`src/lib/selfUpdate/routes.ts:64–81`, `src/lib/selfUpdate/service.ts:2243–2262`, `src/lib/selfUpdate/workEvidence.ts:34–37`, `:62–88`, `:151–157`, `:282–293`, `:312–326`.)
2. The worker calls registry health, the pipeline list and the flow list. Registry health reads both pipeline collections on its unprepared path. The worker's protocol carries the pipeline and flow arrays. The Viewer buffers stdout, parses it at exit and replays the answers. The owner reader separately obtains its registry and flow inputs. Moving the same arrays to another thread still leaves their transfer and decoding on the opening path. (`src/lib/pipelines/store.ts:779–788`, `src/lib/selfUpdate/workReads.ts:29–34`, `:47–53`, `:75–81`, `:103–121`, `src/lib/selfUpdate/workEvidence.ts:190–200`, `src/lib/selfUpdate/instance.ts:320–328`.)
3. The census projects every conversation's generations and continuity paths, visits entries and receipts, and considers every stored headless round. It builds path and custody bindings for later lookups. A host with a writer epoch can also trigger runtime event pagination from cursor zero. The full census answers questions such as which earlier launch shared an artifact. The dialog needs that history only when a current claim points to it. (`src/lib/lifecycle/owners.ts:190–203`, `:283–300`, `:316–331`, `:340–369`, `:403–405`, `:425–452`, `src/lib/selfUpdate/instance.ts:328–360`, `:459–473`.)

## Interactive read

Replace the display call to `probeQuiet` inside `ObservedWork`. Keep its single in-flight read and last observation. Give the reader its own selection of candidates and reuse the process and turn verdicts. The first useful result is a known blocker with its source and observation time, an empty result with complete coverage, or a specific reason coverage is incomplete. Readers see the installation while this work runs. Overlapping GETs, event streams and confirmation dialogs share it. (`src/lib/selfUpdate/workEvidence.ts:263–293`, `:312–326`, `src/lib/selfUpdate/quiet.ts:185–203`, `src/components/selfUpdate/SelfUpdateConfirm.tsx:30–64`.)

## Full audit and switch

Offer **Run full audit** as a deliberate operator action in Update. Use a separate, same-origin operator-gated request. Share one running audit, perform its historical census off the Viewer loop, and return progress, source errors and paged findings tagged with audit time. Include all receipts, generations and old reviewer rounds. Published observations continue while it runs. A refresh, SSE reconnect, background health sample or partial result cannot start an audit. Verify that an ordinary snapshot, an SSE reconnect, and a refused audit request each start zero audits. Preserve the installation-only `work=0` path. The current route treats every other value of `work` as true, so an audit needs explicit dispatch. (`src/lib/selfUpdate/routes.ts:21–26`, `:54–81`, `src/lib/lifecycle/owners.ts:270–286`, `:299–331`, `:340–369`.)

The switch takes fresh evidence at its existing authority boundary. Read the current target, request, gate, launcher PID and start identity, serving generation, live work identities, controller state and drain policy again after asynchronous waits. Rediscover new starts as well as rechecking previously seen owners. Preserve the full authoritative census for decisions that require it. A display limit, a cached empty observation, an audit timestamp or a client-supplied list grants no permission. Checkout compares dispatch versions and gate ownership before reservation. The launcher checks again before taking the request and after its load check. Managed auto admission also re-reads reachability and live work. An explicit override covers only the work its admission allows. Manual checkout revalidates the durable apply request, launcher identity and dispatch version after the build. Managed operator requests go to the deployment owner. Neither receives authorization from the dialog. (`src/lib/selfUpdate/service.ts:690–717`, `:1034–1052`, `:1083–1122`, `:1134–1148`, `:1167–1173`, `:1539–1561`, `:1643–1666`, `:2071–2079`, `src/lib/selfUpdate/quiet.ts:546–561`, `:571–578`, `:606–621`.)

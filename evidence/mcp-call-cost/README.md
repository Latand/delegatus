# MCP call cost regression harness

From a clean checkout with dependencies installed, run:

```sh
bun run scripts/mcp-call-cost-benchmark.ts --base <exact-base-commit>
```

The command archives the selected base and current `HEAD` into temporary source
trees, runs each against fresh generated fixtures and separate `LLV_STATE_DIR`
values, then removes those trees. Each side executes the same 23 healthy
scenarios (303 successful MCP calls) and three failed-verdict index faults,
with three repetitions per fault. It checks that the baseline makes eleven
Viewer HTTP attempts for each fault and the candidate makes one. The fixtures
are generated by the script; no transcript corpus, account state or private
audit input is read. The output contains timings and token-equivalent
aggregates, fixture dimensions, and fault attempt counts.

The timing profile includes controlled delays for remote-command and
browser-arrival paths. Treat those rows as harness behavior, not production
latency. Healthy timings are local synthetic measurements and can vary with
host load.
